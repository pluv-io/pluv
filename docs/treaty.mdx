---
title: "Treaty"
description: "Share user, presence, and storage schemas between @pluv/io and @pluv/client with createTreaty"
---

User, presence, and storage used to be split across `authorize.user`, `createIO({ crdt })`, and `createClient({ presence, storage })`. Define them once as a **treaty** and import the same value on the server and the client.

User, presence, and client metadata must be [Standard Schema](https://standardschema.dev) libraries that also implement [Standard JSON Schema](https://standardschema.dev/json-schema) on the **same object** (Zod 4.2+ or ArkType today). `createTreaty` and `createClient().config({ metadata })` throw if `jsonSchema` is missing.

## Create a treaty

Put this in a shared module both sides can import:

```ts
// shared/treaty.ts
import { createTreaty } from "@pluv/treaty";
import { s } from "@pluv/crdt";
import { yjs } from "@pluv/crdt-yjs";
import { z } from "zod";

const t = createTreaty({
  user: z.object({
    id: z.string(),
    name: z.string(),
  }),
  presence: z.object({
    selectionId: z.string().nullable(),
  }),
  storage: yjs.schema({
    messages: yjs.yArray(s.string()),
  }),
});

const select = t.procedure.presence
  .input(z.object({ id: z.string().nullable() }))
  .resolve(({ id }, { user, presence }) => ({ selectionId: id }));

const addMessage = t.procedure.storage
  .input(z.object({ text: z.string() }))
  .resolve(({ text }, { storage }) => {
    storage.messages.push([text]);
  });

export const treaty = t.router({
  select,
  addMessage,
});
```

`user` is required. `presence` and `storage` are optional. Procedures are optional too. `createTreaty({ user })` with no `.router()` is valid.

Presence resolvers receive `{ user, presence, json }`. Storage resolvers also receive writable `storage`. `presence` is a snapshot; mutating it does not update the room. Presence updates only via the returned patch. `json` is computed on first access. Invoke them on the room. Remotes apply the resulting `$presenceUpdated` / storage updates and do **not** re-run `select` / `addMessage`.

```ts
room.presence.select({ id: "item-1" });
room.storage.addMessage({ text: "hello" });
```

Storage resolvers run inside `room.transact` by default. Pass `{ transact: false }` when the resolver should own commit (for example Loro):

```ts
const addMessage = t.procedure.storage
  .input(z.object({ text: z.string() }))
  .resolve(({ text }, { storage }) => {
    storage.messages.push([text]);
  }, { transact: false });
```

If `transact: false` and you commit **after** `resolve` returns, `$updateStorage` will not include the procedure name.

Do not destructure `room.presence` / `room.storage` (or `usePresence()` / `useStorage()`). Each property access allocates a new function, same as `room.broadcast`. Hold the proxy.

`useStorage()` is that command proxy. Read a CRDT field with `useStorageField("messages")`. Raw `updateMyPresence`, `transact`, and native types from `useStorageField` stay as escape hatches.

## Pass it to io and the client

```ts
import { createIO } from "@pluv/io";
import { platformNode } from "@pluv/platform-node";
import { treaty } from "../shared/treaty";

const io = createIO()
  .platform(platformNode())
  .config({
    treaty,
    secret: process.env.PLUV_AUTH_SECRET!,
    context: () => ({ db }),
  });
```

```ts
import { createClient } from "@pluv/client";
import type { ioServer } from "./server/pluv-io";
import { treaty } from "../shared/treaty";

const client = createClient<typeof ioServer>().config({
  treaty,
  authEndpoint: ({ room }) => `/api/pluv/auth?room=${room}`,
  initialStorage: { messages: [] },
});
```

Keep `createClient<typeof ioServer>()` for **events**. Presence, storage, and user types come from that server treaty. Always pass the runtime `treaty` too; a type-only import of `ioServer` cannot recover schemas.

- Node and Cloudflare: `secret` is required (`string` or `(initContext) => string`).
- Hosted `platformPluv`: omit `secret` (`secretKey` stays on `platformPluv(...)`).
- `getInitialStorage` is required when `treaty.storage` is a real CRDT.
- `initialPresence` / `initialStorage` remain JSON seeds.
