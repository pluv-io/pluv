---
title: "Authorization"
description: "Learn how to add custom authorization to rooms in @pluv/io"
---

pluv.io uses JWTs to authorize access to rooms on a new connection. To generate a JWT, you will need to setup an authentication endpoint to determine if the user should have access to the room.

The examples below will use [hono](https://hono.dev), but so long as you can create an http endpoint that can return text responses, the documentation below should still be relevant.

You can view another example of these via your platform's respective quickstart guides:

1. [Next.js](/docs/quickstart/nextjs)
2. [Cloudflare Workers](/docs/quickstart/cloudflare-workers)
3. [Node.js](/docs/quickstart/nodejs)

## Enable authorization on io

Put the user schema on a shared [treaty](/docs/guides/treaty). The `user` schema must always include `id`. Node and Cloudflare also take `secret` on `.config()` (`string` or `(initContext) => string`). Hosted `platformPluv` omits `secret`.

User, presence, and client metadata must be a [Standard Schema](https://standardschema.dev) library that also implements Standard JSON Schema on the same object (Zod 4.2+ or ArkType). The examples below use Zod.

```ts
// shared/treaty.ts
import { createTreaty } from "@pluv/treaty";
import { z } from "zod";

export const treaty = createTreaty({
  user: z.object({
    id: z.string(),
    name: z.string(),
  }),
});
```

```ts
// server/io.ts
import { createIO } from "@pluv/io";
import { platformNode } from "@pluv/platform-node";
import { treaty } from "../shared/treaty";

export const io = createIO()
  .platform(platformNode())
  .config({
    treaty,
    secret: process.env.PLUV_AUTH_SECRET!,
  });

export const ioServer = io.server();
```

## Owner operator sessions

App owners can join the same room WebSocket with a different JWT **kind**, not a second protocol and not impersonation. Opt in with `onGetOperator` on `io.server()`. The hook maps a closed `OperatorUser` to your treaty user, and that user is stored on the token. Missing hook, `null`, or a parse failure means no token. Mint operator tokens with `ioServer.createToken`.

```ts
type OperatorUser = {
  id: string;
  name: string;
  imageUrl: string | null;
};

export const io = createIO()
  .platform(platformNode())
  .config({
    treaty,
    secret: process.env.PLUV_AUTH_SECRET!,
  });

export const ioServer = io.server({
  onGetOperator: ({ room, operator }) => {
    if (!canOperate(room, operator.id)) return null;

    return { id: `owner:${operator.id}`, name: operator.name };
  },
});

const token = await ioServer.createToken({
  request: c.req.raw,
  room,
  kind: "operator",
  operator: {
    id: owner.id,
    name: owner.name,
    email: owner.email,
    imageUrl: owner.imageUrl,
  },
});
```

`email` is passed to `onGetOperator` while minting, then dropped. It is not stored on the token, the session, or room events.

`register` reads `user` and `operator` from the token. The hook does not run again. A token stays valid until it expires. An open socket keeps that answer until it disconnects. The websocket is not tied to the token lifetime.

`maxConnections` and room lifetime count every open socket, including operators. Default `connectionCount` and `userCount` stay users. An open operator socket uses a slot and holds the room after the last user leaves.

Default `listUsers`, `getOthers`, `useOthers`, `getRoomStats`, and `useRoomStats` stay users. Pass `{ kinds: ["operator"] }` or `{ kinds: ["user", "operator"] }` on `listUsers`, `getOthers`, `useOthers`, `getRoomStats`, and `useRoomStats`. A single person is `getOther` / `useOther` with that user's id. Pass `{ kind: "operator" }` for the operator. Omit `kind` and a person who is only an operator is null. Treaty resolvers still receive mapped `user`; operators also get `operator`. ACL on `user.id` sees that mapped identity — prefer derived ids that do not collide with live users unless the owner is the same person in two tabs (still two kinds; presence is not shared).

Hosted `@pluv/platform-pluv` cannot mint operator tokens yet.

## Setup an authorization endpoint

To add custom authorization, you'll need to define an http endpoint to return a JWT from.

```ts
// server/server.ts
import { serve, type HttpBindings } from "@hono/node-server";
import Http from "http";
import { Hono } from "hono";
import { ioServer } from "./io";

const PORT = 3000;

const app = new Hono<{ Bindings: HttpBindings }>()
  .get("/api/pluv/auth", async (c) => {
    const room = c.req.query("room") as string;
    const user = await getUser(c.req.raw);
    const token = await ioServer.createToken({ request: c.req.raw, room, user });

    return c.text(token, 200);
  });

const server = serve({ fetch: app.fetch, port: PORT }) as Http.Server;
const wsServer = new Ws.WebSocketServer({ server });
```

## Connect to your authorization endpoint

Now that we have your endpoint defined, connect your frontend client to your authorization endpoint.

```ts
// frontend/io.ts
import { createClient } from "@pluv/react";
import type { ioServer } from "server/io";

const client = createClient<typeof ioServer>().config({
  treaty,
  // Specify your auth endpoint here
  // Set to `true` if you have authorization on your io instance, and you
  // want to use the default of (room) => `/api/pluv/authorize?room=${room}`
  // This is the default from `createPluvHandler`
  authEndpoint: ({ room }) => `/api/pluv/auth?room=${room}`,
  // ...
});
```

### How to use POST requests

```ts
// frontend/io.ts
import { createClient } from "@pluv/react";
import type { ioServer } from "server/io";

const client = createClient<typeof ioServer>().config({
  treaty,
  authEndpoint: ({ room }) => ({
    url: "/api/authorize",
    // You can use fetch options as well like so
    options: {
      method: "POST",
      body: JSON.stringify({ room }),
    },
  }),
  // ...
});
```

## Add token to room registration

When the frontend receives a JWT from your authorization endpoint, it will add that token as a `token` query parameter to your websocket connection request. To use this token, pass the token into `IORoom.register` on your server.

```ts
import { serve, type HttpBindings } from "@hono/node-server";
import Http from "http";
import { Hono } from "hono";
import { ioServer } from "./io";

const PORT = 3000;

const app = new Hono<{ Bindings: HttpBindings }>()
  .get("/api/pluv/auth", async (c) => {
    // ...
    return c.text(token, 200);
  });

const parseRoomId = (url: string): string => {
  /* get room from req.url */
};

const parseToken = (url: string): string => {
  /* get token from query parameters of req.url */
};

const getRoom = (roomId: string): InferIORoom<typeof ioServer> => { /* ... */};

wsServer.on("connection", async (ws, req) => {
  const roomId = parseRoomId(req.url);
  const token = parseToken(req.url);
  const room = getRoom(roomId);

  // Pass in the token from query params
  await room.register(ws, { request: req, token });
});
```
