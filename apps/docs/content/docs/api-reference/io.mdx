## createIO

`createIO().platform(platform).config(options)` returns a `PluvIO`. `platform` is a factory, as in `platformNode()`. See [Authorization](/docs/guides/authorization), [Cloudflare Workers](/docs/quickstart/cloudflare-workers), and [Node.js](/docs/quickstart/nodejs).

`options`:

- `treaty` — the shared treaty
- `secret` — a string, or `(init) => string`. `init` is `{ request }` on Node and `{ env, request }` on Cloudflare
- `context` — a value, or a function of the room context (`{ env, state }` on Cloudflare). Listeners on `io.server()` receive it
- `debug` — `boolean`
- `limits`
  - `maxConnections` — live sockets in a room. Default `256`
  - `presenceMaxSize` — bytes. Default `512`
  - `storageMaxSize` — bytes. Default `31457280`
  - `userIdMaxLength` — characters. Default `128`
  - `userMaxSize` — bytes for one session's stored user objects. Default `512`
  - `dangerouslyAllowHighPresenceFanout` — allow a `maxConnections` value that would otherwise be rejected

```ts
import { createIO } from "@pluv/io";
import { platformNode } from "@pluv/platform-node";
import { Database } from "./db";
import { treaty } from "./shared/treaty";

const io = createIO()
  .platform(platformNode())
  .config({
    treaty,
    secret: process.env.PLUV_AUTH_SECRET!,
    context: () => ({
      db: new Database(process.env.DATABASE_URL!),
    }),
  });
```

## PluvIO

This is the client returned by `createIO`.

### createToken

Returns `Promise<string>`.

Mints a room JWT from an auth endpoint. See [Authorization](/docs/guides/authorization).

User token, on `io.createToken`:

- `room` — room id
- `user` — treaty user. Omit `kind`, or pass `"user"`
- `maxAge` — milliseconds. Default `60000`
- `request` — `Request | IncomingMessage` on Node
- `env` and `request: Request` — both required on Cloudflare

Operator token, on `ioServer.createToken`. Requires `onGetOperator` on `io.server()`:

- `room`
- `kind: "operator"`
- `operator` — `{ id, name, email, imageUrl }`
- `maxAge`, and the same platform fields as a user token

```ts
const token = await io.createToken({
  request,
  room: "my-example-room",
  user: { id: "...", name: "..." },
});

const operatorToken = await ioServer.createToken({
  request,
  room: "my-example-room",
  kind: "operator",
  operator: { id: "...", name: "...", email: "...", imageUrl: null },
});
```

### procedure

Creates a new type-safe event procedure to be broadcasted from `PluvClient`. See [Define Events](/docs/guides/events/server) for more information.

```ts
import { z } from "zod";

const sendMessage = io.procedure
  .input(z.object({ message: z.string() }))
  .broadcast(({ message }) => ({ receiveMessage: { message } }));

const doubleValue = io.procedure
  .input(z.object({ value: z.number() }))
  .broadcast(({ value }) => ({ receiveValue: { value: value * 2 } }));

const wave = io.procedure
  .broadcast(() => ({ receiveMessage: { message: "Hello world!" } }));
```

### router

Creates a new type-safe event procedure router to attach events and connect to a `PluvServer`.

```ts
const router = io.router({
  sendMessage,
  doubleValue,
  wave,
});
```

### mergeRouters

Returns one router. Event names must be unique across the routers you pass. A repeated name throws.

```ts
const messaging = io.router({ sendMessage });
const presence = io.router({ wave });

const router = io.mergeRouters(messaging, presence);

const server = io.server({ router });
```

### server

Creates a `PluvServer` that will create rooms to register your websockets to.

In the example below, not all event listeners are available for all platforms. Refer to the TypeScript intellisense for your selected platform when defining your server to know which you can use.

```ts
const router = io.router({ /* ... */ });

const server = io.server({
  // Triggered when a room is freshly created. If the room existed before, you
  // can load the storage state for the room by returning it here
  // This is required if `treaty.storage` is a real CRDT. This is to
  // prevent storage data loss on intermittent connections
  getInitialStorage: async ({ context, room }) => {
    const { db } = context;
    const existingRoom = await db.room.findUnique({ where: { room } });

    return existingRoom?.encodedState ?? null;
  },
  // Optional: Triggered when a room is destroyed. Use for cleanup if needed.
  // This event does NOT include encodedState to prevent accidentally saving
  // empty or uninitialized storage data.
  onRoomDestroyed: async ({ context, room }) => {
    // Room destroyed - use for cleanup if needed
  },
  // Optional: Triggered when storage is about to be destroyed. Only fires
  // when storage was initialized via initializeSession. Callback includes
  // the last value for the room's state for persisting purposes
  onStorageDestroyed: async ({ context, encodedState, room }) => {
    const { db } = context;

    await db.room.upsert({
      where: { room },
      create: { encodedState, room },
      update: { encodedState },
    });
  },
  // Optional: Triggered each time any participant sends a new message to
  // other participants
  // It is advised not to perform any heavy operations in this listener
  // due to the frequency of invocations
  onRoomMessage: async ({ context, room }) => {
    // ...
  },
  // Optional: Triggered after the room writes the document into server storage.
  onStorageSnapshot: ({ context, encodedState, room }) => {
    // ...
  },
  // Optional: Reports document changes about once a second. This is not every
  // update in the document. Use the snapshot for the full document, and handle
  // gaps yourself. Storage already saved when the room opens is not reported.
  // An update that arrives before the changes it depends on is reported only
  // after those changes arrive. The part that already applied is saved with the
  // room, and if the room closes first it never appears here. Updates past the
  // document size limit can land in the document and still be left out. If this
  // listener throws, that batch is not sent again.
  onStorageEdits: ({ context, room, changes }) => {
    // changes: { update, user, operator, procedure }[]
  },
  // Optional: Triggered each time a user connects to a room
  onUserConnected: ({ context, encodedState, room, user }) => {
    // ...
  },
  // Optional: Triggered each time a user disconnects from a room
  onUserDisconnected: ({ context, encodedState, room, user }) => {
    // ...
  },
  // Optional: Map an operator JWT to a treaty user. Required to mint or
  // register owner operator sessions
  onGetOperator: ({ room, operator }) => {
    return { id: `owner:${operator.id}` };
  },
  // Optional. Only needed if specifying events
  router,
});

// Can also be created without a router, if events are unneeded
const server = io.server();
```

## PluvServer

### io

The `createIO()` instance this server was built from.

```ts
const ioServer = io.server();

ioServer.io;
```

### createRoom

Returns the room. Attach sockets with `manageSessions`.

Creates a room with the specified id. For platforms that require room context (e.g., Cloudflare requires `env` and `state`), these must be provided as the second argument. `manageSessions` hydrates hibernated sockets. `register`, `onMessage`, `onClose`, `onError`, `broadcast`, `evict`, and `garbageCollect` are called on that return value. Host procedure calls are on the [experimental](/docs/api-reference/experimental) page.

```ts
// For platforms without required room context (e.g., Node.js)
const room = server.createRoom("my-example-room");

// For platforms with required room context (e.g., Cloudflare)
const room = server.createRoom("my-example-room", { env, state });
```

> **Note**: All event listeners (e.g., `onRoomDestroyed`, `onStorageDestroyed`) are configured at the server level via `io.server()`, not when creating individual rooms.

## manageSessions

```ts
import { manageSessions } from "@pluv/io";

const room = server.createRoom("my-example-room");
const sessions = manageSessions(room);
```

`sessions` is the socket list. The methods below are called on it. Host procedure calls are on the [experimental](/docs/api-reference/experimental) page.

## IORoom

This is the room returned by `PluvServer.createRoom`. Websockets are registered through `manageSessions`.

### broadcast

Returns `Promise<void>`.

Broadcasts an event to all connected websockets to the room.

```ts
// The below 2 statements are equivalent
sessions.broadcast("sendMessage", { message: "Hello world~!" });

sessions.broadcast.sendMessage({ message: "Hello world~!" });
```

### evict

Returns `Promise<void>`

Disconnects a connection from the room by connection id.

```ts
sessions.evict(connectionId);
```

### evictAll

Returns `Promise<void>`

Disconnects all connections from the room. Effectively destroys the room, as rooms automatically destroy when empty.

```ts
sessions.evictAll();
```

### garbageCollect

Returns `Promise<void>`

While uncommon and unusual, there may be edge cases that may cause stale connections to persist either in user's browsers, or in the `IORoom`. Such can be missed websocket messages or server errors that weren't gracefully handled. `@pluv/platform-node` will automatically run garbage collection periodically; however, for `@pluv/platform-cloudflare`, it is recommended that this is called in a Durable Object alarm periodically.

```ts
sessions.garbageCollect();
```

### getSize

Returns `number`

Returns the current count of active connections in the room

```ts
sessions.getSize();
```

### listUsers

Returns `ListUsersResult`

`listUsers(options?)` returns `ListUsersResult`. Synchronous identity page, with no presence. Forward-only. Defaults to users. Rows are grouped by `kind` and `data.id`, and each row is `{ data, kind, operator }`.

`options`:

- `cursor` — `{ kind: "user" | "operator", id: string } | null`. `endCursor` from the previous page
- `kinds` — `readonly ("user" | "operator")[]`. Omit for users
- `limit` — integer from 1 to 100. Default `50`

A bad `limit` returns `{ success: false, error: { code: "INVALID_LIMIT" } }`. The client method is a promise and also returns `FAILED` and `NOT_CONNECTED`. See [`room.listUsers`](/docs/api-reference/client#pluvroomlistusers). Wrap this in your own HTTP handler to expose it off-socket.

```ts
const result = sessions.listUsers({ cursor: null, limit: 50 });

if (!result.success) {
  // result.error.code: "INVALID_LIMIT"
  return;
}

// result.users: { data, kind, operator }[]
// result.pageInfo.hasNextPage, result.pageInfo.endCursor
```

### id

Type of `string`.

This is the id of the room, when the room was created.

```ts
const roomId = sessions.id;
```

### register

Returns `Promise<void>`.

`register(webSocket, options)` attaches a socket. On Node, `options` is `{ request: Request | IncomingMessage, token?: string }`. On Cloudflare, `options` is `{ env, request: Request, token?: string }`. The host forwards `message`, `close`, and `error` to `onMessage`, `onClose`, and `onError`. On Node, attach those listeners before awaiting `register`, because `ws` drops frames that arrive with no listener. See [Cloudflare Workers](/docs/quickstart/cloudflare-workers), [Node.js](/docs/quickstart/nodejs), and [Authorization](/docs/guides/authorization).

```ts
// Node
await sessions.register(webSocket, { request, token });

// Cloudflare
await sessions.register(webSocket, { env, request, token });
```

### onMessage

Returns `(event) => Promise<void>`

Handles one WebSocket `message` for a socket that has already been registered. Pass the socket, then call the returned function with `{ data }`.

```ts
ws.on("message", async (data) => {
  await sessions.onMessage(ws)({ data });
});
```

### onClose

Returns `(event) => Promise<void>`

Handles one WebSocket `close`. `event` is `{ code, reason }`.

```ts
ws.on("close", async (code, reason) => {
  await sessions.onClose(ws)({ code, reason: reason.toString() });
});
```

### onError

Returns `(event) => Promise<void>`

Handles one WebSocket `error` and disconnects that socket.

```ts
ws.on("error", async (error) => {
  await sessions.onError(ws)({ error, message: error.message });
});
```
