---
title: "Migrate to v6"
description: "Breaking changes when upgrading from pluv.io v5 to v6, including the treaty contract, CRDT schema builder, createIO/createClient builders, and JSON-only storage seeds."
---

## Treaty replaces authorize.user, crdt, and client presence/storage

User, presence, and storage are one isomorphic [treaty](/docs/guides/treaty). Import the same value on the server and the client. `authorize.user`, `crdt: yjs | loro`, and client `presence` / `storage` options are removed. JWT leftover is `secret`. `yjs.storage` / `loro.storage` are gone. `yjs.schema` / `loro.schema` are the factories.

```ts
// shared/treaty.ts
import { createTreaty } from "@pluv/treaty";
import { s } from "@pluv/crdt";
import { yjs } from "@pluv/crdt-yjs";
import { z } from "zod";

const t = createTreaty({
  user: z.object({
    id: z.string(),
    name: z.string(),
  }),
  presence: z.object({
    selectionId: z.string().nullable(),
  }),
  storage: yjs.schema({
    messages: yjs.yArray(s.string()),
  }),
});

const select = t.procedure.presence
  .input(z.object({ id: z.string().nullable() }))
  .resolve(({ id }) => ({ selectionId: id }));

const addMessage = t.procedure.storage
  .input(z.object({ text: z.string() }))
  .resolve(({ text }, { storage }) => {
    storage.messages.push([text]);
  });

export const treaty = t.router({
  select,
  addMessage,
});
```

```ts
// Before
const io = createIO()
  .platform(platformNode())
  .config({
    authorize: { secret, user: schema },
    context,
  });

const client = createClient<typeof ioServer>().config({
  authEndpoint: () => "",
  presence: z.object({ selectionId: z.string().nullable() }),
  storage: yjs.storage({
    schema: yjs.schema({ messages: yjs.yArray(s.string()) }),
  }),
});

// After
const io = createIO()
  .platform(platformNode())
  .config({
    treaty,
    secret,
    context,
  });

const client = createClient<typeof ioServer>().config({
  authEndpoint: () => "",
  treaty,
  initialStorage: { messages: [] },
});
```

Hosted pluv omits `secret` (`secretKey` stays on `platformPluv({ ... })`). Node and Cloudflare still require `secret` (`string` or `(initContext) => string`).

User, presence, and client metadata must implement Standard Schema and Standard JSON Schema on the same object (Zod 4.2+ or ArkType). `createTreaty` and `createClient().config({ metadata })` throw if `jsonSchema` is missing.

## createClient is type-arg then config

`infer((i) => ({ io }))` and `createClient({ types, ... })` are removed. Bind the server type as a type argument for **events**, then pass the shared `treaty` and metadata to `.config()`.

```ts
import type { ioServer } from "./server/pluv-io";
import { treaty } from "./shared/treaty";

// Before
const types = infer((i) => ({ io: i<typeof ioServer> }));
const client = createClient({
  types,
  authEndpoint: () => "",
  presence: z.object({ selectionId: z.string().nullable() }),
});

// After
const client = createClient<typeof ioServer>().config({
  authEndpoint: () => "",
  treaty,
});
```

Do not call `createClient<TIO>(options)`. That freezes inference. `createClient().config({ ... })` still works when you do not have a server type. Always pass the runtime treaty; a type-only import of `ioServer` cannot recover schemas.

Cloudflare/Node `infer((i) => ({ env }))` on the platform is unchanged.

## Storage schema and JSON seeds

`yjs.doc((t) => …)` and `loro.doc((t) => …)` builders are removed. Declare storage with `yjs.schema` / `loro.schema` on the treaty. Seed with JSON in `initialStorage`.

JSON schema leaves live on `s` from `@pluv/crdt`. Top-level fields must be that library's CRDT nodes (`yjs.yArray`, `loro.loroList`, …).

```ts
import { s } from "@pluv/crdt";
import { yjs } from "@pluv/crdt-yjs";
import type { ioServer } from "./server/pluv-io";
import { treaty } from "./shared/treaty";

// Before
createClient({
  types,
  initialStorage: yjs.doc((t) => ({
    messages: t.array<string>("messages", ["hello"]),
  })),
});

// After
createClient<typeof ioServer>().config({
  treaty,
  initialStorage: {
    messages: ["hello"],
  },
});
```

Room-level `initialStorage` is JSON only, not a builder function:

```tsx
// Before
<PluvRoomProvider
  room="my-room"
  initialStorage={(t) => ({
    messages: t.array("messages", ["hello"]),
  })}
/>

// After
<PluvRoomProvider
  room="my-room"
  initialStorage={{
    messages: ["hello"],
  }}
/>
```

Missing seed keys become empty containers. Extra keys throw. Xml/tree types are not JSON-seedable. Declare them on the schema and initialize at editor bind time.

`getInitialStorage` is required when `treaty.storage` is a real CRDT. Do not pass `storage` or `crdt` to `createIO().config()` or `io.server`.

## Named presence/storage calls and `useStorageField`

Invoke procedures on the client room:

```ts
room.presence.select({ id: "item-1" });
room.storage.addMessage({ text: "hello" });
```

React: `usePresence()` / `useStorage()` return those proxies. `useStorage(key)` is now `useStorageField(key)`:

```ts
const [messages, sharedType] = useStorageField("messages");
const storage = useStorage();

storage.addMessage({ text: "hello" });
```

Storage procedures wrap `room.transact` unless `.resolve(fn, { transact: false })`. Do not destructure the proxies.

## Native shared types

`CrdtType`, `YjsType`, `LoroType`, and `InferCrdtJson` are removed. `useStorageField` and `getStorage` return native types (`Y.Array`, `LoroList`, …), not wrappers with a `.value` property.

```ts
// Before
const messages: yjs.YjsType<YArray<string>, string[]> | null = room.getStorage("messages");
messages?.value.push(["world"]);

// After
const messages: YArray<string> | null = room.getStorage("messages");
messages?.push(["world"]);
```

Runtime nested inserts still use `yjs.map()` / `yjs.text()` / `loro.object()` / `loro.list()`. Those helpers return native constructors.

## Combinators

Unions, intersections, optionals, and similar combinators are `$`-prefixed on `s` (`s.$union`, `s.$optional`, …). Serialized `kind` values are unprefixed (`"union"`, `"optional"`, …).

## createIO is platform-then-config

`createIO` is no longer a one-shot call. Pass a named platform helper to `.platform()`, then put `treaty`, `secret`, and `context` on `.config()`. Platform helpers no longer take authorize or crdt.

```ts
const io = createIO()
  .platform(platformNode())
  .config({
    treaty,
    secret,
    context,
  });

export const ioServer = io.server({ router, getInitialStorage });
```

## UserInfo is a person

`UserInfo` is `{ data, presence }`. Lookup is `data.id` (`getOther` / `useOther`).

`getOthers()` / `useOthers()` stay the presence-bearing set in mode `all`. Room size is `getRoomStats` / `useRoomStats`. `listUsers({ cursor, limit })` pages everyone currently in the room (including you), identities only, on the client room and on `IORoom`.

Procedure and size-limit failures arrive on `room.subscribe.error` / `useRoomError`.

Default `maxConnections` is 256. Raising it for a large room requires `dangerouslyAllowHighPresenceFanout: true`.

## Redis pubsub and procedure.sync are gone

`@pluv/pubsub-redis` is removed. `io.procedure.sync()` is removed. A live room (occupancy, presence, `listUsers`) is not split across Node processes.

`@pluv/persistence-redis` still persists CRDT storage. `platformNode({ persistence })` no longer takes a `pubSub`. If you used `.sync()` on a procedure, move that work to `.self()` or `.broadcast()`.
