---
title: "Migrate to v6"
description: "Breaking changes when upgrading from pluv.io v5 to v6, including the CRDT schema builder, createIO/createClient builders, and JSON-only storage seeds."
---

## createClient is type-arg then config

`infer((i) => ({ io }))` and `createClient({ types, ... })` are removed. Bind the server type as a type argument, then pass presence, storage, and metadata to `.config()`.

```ts
import type { ioServer } from "./server/pluv-io";

// Before
const types = infer((i) => ({ io: i<typeof ioServer> }));
const client = createClient({
  types,
  authEndpoint: () => "",
  presence: z.object({ selectionId: z.string().nullable() }),
});

// After
const client = createClient<typeof ioServer>().config({
  authEndpoint: () => "",
  presence: z.object({ selectionId: z.string().nullable() }),
});
```

Do not call `createClient<TIO>(options)` — that freezes presence and storage inference. `createClient().config({ ... })` still works when you do not have a server type.

Cloudflare/Node `infer((i) => ({ env }))` on the platform is unchanged.

## Storage schema and JSON seeds

`yjs.doc((t) => …)` and `loro.doc((t) => …)` builders are removed. Declare storage with `yjs.schema` / `loro.schema`, wrap it in `yjs.storage` / `loro.storage` on `createClient().config()`, and seed with JSON in `initialStorage`.

JSON schema leaves live on `s` from `@pluv/crdt`. Top-level fields must be that library's CRDT nodes (`yjs.yArray`, `loro.loroList`, …).

```ts
import { s } from "@pluv/crdt";
import { yjs } from "@pluv/crdt-yjs";
import type { ioServer } from "./server/pluv-io";

// Before
createClient({
  types,
  initialStorage: yjs.doc((t) => ({
    messages: t.array<string>("messages", ["hello"]),
  })),
});

// After
createClient<typeof ioServer>().config({
  storage: yjs.storage({
    schema: yjs.schema({
      messages: yjs.yArray(s.string()),
    }),
  }),
  initialStorage: {
    messages: ["hello"],
  },
});
```

Room-level `initialStorage` is JSON only, not a builder function:

```tsx
// Before
<PluvRoomProvider
  room="my-room"
  initialStorage={(t) => ({
    messages: t.array("messages", ["hello"]),
  })}
/>

// After
<PluvRoomProvider
  room="my-room"
  initialStorage={{
    messages: ["hello"],
  }}
/>
```

Missing seed keys become empty containers. Extra keys throw. Xml/tree types are not JSON-seedable — declare them on the schema and initialize at editor bind time.

The server still takes `createIO().platform(...).config({ crdt: yjs })` (or `loro`) and an empty `doc()`. Do not pass `storage` to `.config()` or `io.server`.

## Native shared types

`CrdtType`, `YjsType`, `LoroType`, and `InferCrdtJson` are removed. `useStorage` and `getStorage` return native types (`Y.Array`, `LoroList`, …), not wrappers with a `.value` property.

```ts
// Before
const messages: yjs.YjsType<YArray<string>, string[]> | null = room.getStorage("messages");
messages?.value.push(["world"]);

// After
const messages: YArray<string> | null = room.getStorage("messages");
messages?.push(["world"]);
```

Runtime nested inserts still use `yjs.map()` / `yjs.text()` / `loro.object()` / `loro.list()`. Those helpers return native constructors.

## Combinators

Unions, intersections, optionals, and similar combinators are `$`-prefixed on `s` (`s.$union`, `s.$optional`, …). Serialized `kind` values are unprefixed (`"union"`, `"optional"`, …).

## createIO is platform-then-config

`createIO` is no longer a one-shot call. Pass a named platform helper to `.platform()`, then put `authorize`, `context`, and `crdt` on `.config()`. Platform helpers no longer take authorize or crdt.

```ts
const io = createIO()
  .platform(platformNode())
  .config({
    authorize: { secret, user: schema },
    context,
    crdt: yjs,
  });

export const ioServer = io.server({ router, getInitialStorage });
```

Hosted pluv keeps JWT-less `authorize: { user }` on `.config()` and `secretKey` on `platformPluv({ ... })`. Node and Cloudflare still require `authorize.secret`.
